설정집의 나머지 디테일은 사용자 핵심을 보존해 작성한 제작 기본값이다. 구현자는 이를 현재 정사로 적용하며 모순이나 구현 제약이 발견되면 문서를 먼저 수정하고 변경 이유를 기록한다. 기본값을 또 미확정으로 취급해 첫 단계부터 질문을 반복하지 않는다.

이번 인수인계는 기획 문서다. 코드 구현·자산 제작·플레이 테스트·배포는 수행하지 않았다. 다음 구현에서 기존 호텔 벨루아 사건을 1편의 금 트로피 사건으로 교체한다. 2·3편은 플레이 가능 상태로 만들지 않는다. 새 프로젝트 생성, AI 공급자 교체, 배포는 이 문서만으로 요구하지 않는다.

## 2. 유지할 게임 경험

자료의 근거 문장을 저장하고 자유 대화에 제시해 거짓말을 깬다. 세 용의자는 준서(A), 민아(B), 태준(C)뿐이다. 수사팀은 원본 조회·감정 요청을 받는 별도 기능이다. 준서와 민아는 거짓말하지 않으며 태준의 은폐만 논파한다. 무고한 인물에 거짓 자백이나 인정 이벤트를 붙이지 않는다.

처음은 GT-E01~03만 보유한다. 나머지 자료는 모두 수사팀에 자연어로 요청해서 얻는다. 용의자는 사실이나 조사 단서를 말하고 사건 진술은 기록되지만 외부 증거 문서를 자동 지급하지 않는다. 명확한 복합·광범위 요청도 받아들이며 인위적인 선행 논파 잠금은 없다. 권장 발견 순서는 설정집 11절을 따른다.

영상·CCTV·녹음·전달 사진·매입 사진·봉인·청소 도구·동료의 문 잡아주기·제4의 목격자 캐릭터를 추가하지 않는다. 흉기는 원래 진열대에서 민아가 가져간다. 태준이 건네주는 연출을 넣지 않는다. 이름이 필요한 실존 인물·브랜드·은행 계좌번호를 새로 만들지 않는다.

## 4. 권장 구현 순서

1. 새 사건 데이터와 타입부터 만든다. 초기 보유, 질문, 문장 ID, 네 논파, 최종 조건, 요청 카탈로그를 연결한다. 기존 질문·논파 엔진을 재사용하되 게임 진실은 AI 호출 없이 검증 가능해야 한다.
2. 새 사건 판정 테스트를 통과시킨다. C-L03의 생존 추론 반박과 C-L04의 예약 작성자 확정을 구분한다. 20:55 인수만으로 20:48 이전 공격을 확정하지 않는다.
3. 수사팀의 자유 요청 해석·고정 결과 지급을 구현한다. 인물의 답으로 문서 자동 지급되는 구 사건 경로를 제거한다.
4. 수사팀 탭과 자료함 연결, 요청 재시도·저장·중복 처리를 구현한다. 인물 탭에서 수사팀으로 이동해도 대화 문맥을 각 대상별로 유지한다.
5. 프로필·힌트·보고서·에피소드·지도·이미지 참조를 교체한다. 모든 구 사건 문구·독살/가짜 유서/영상 등 구 증거 잔재를 사용처 기준으로 검사한다.
6. 순차 경로, 조기 분석 경로, 전체 자료 조회 경로를 실제 AI 대화로 끝까지 플레이한다. 빌드 성공만으로 재미·대기·일관성 검증을 대체하지 않는다.
7. 구현 결과·남은 자산·검증 결과를 문서에 기록한다. 배포는 별도 요청이 있을 때 진행한다.

## 5. 최소 데이터 계약

```ts
// 권장 형태. 기존 타입에 맞춰 조정하되 의미는 유지한다.
type CaseId = 'gold-trophy';
type InvestigationStatus =
  | 'completed' | 'needs_object' | 'unsupported'
  | 'clarify' | 'already_owned';
interface InvestigationDef {
  id: string;              // GT-R01...
  topic: string;
  aliases: string[];
  outputs: string[];       // GT-E04...
  dependencies?: string[]; // 다른 조사 ID, 요청 범위가 허용하면 연속 수행
  resultText: string;       // 공개 가능한 고정 결과
}
interface InvestigationReceipt {
  requestId: string;        // 한 제출의 고유 ID, 재시도도 동일
  investigations: string[];
  outputs: string[];
  status: InvestigationStatus;
}
```

근거 문장 ID는 설정집의 GT-E##.##를 유지한다. 각 자료의 본문에 없는 주장을 summary나 AI context에 넣지 않는다. 공개 전 답변 목록에 작가용 공격 시각·자백·최종 조건 설명이 노출되지 않도록 한다. 범인 역할 생성 프롬프트는 태준의 현재 유효한 거짓 답을 포함하되, 자연스럽게 솔직한 비밀을 흘리도록 지시하지 않는다.

인물 질문의 `record`는 사건 진술 기록을 뜻한다. 증거 `reveals`는 질문에 넣지 않는다. 논파 성공으로는 인정 진술·상태만 추가한다. GT-E04 이후 모든 외부 자료는 조사 완료 reducer/handler에서만 보유 목록으로 들어간다.

A-Q/B-Q/C-Q의 질문 답과 C-R 인정 진술은 서로 구분한다. 논파 대상은 거짓인 태준 발언만이다. 최종 공격·예약 조작은 설정집 F01~05의 자료 및 실제 제시를 검증한다. `Cond`만으로 복합 의미가 표현되지 않으면 작은 별도 함수를 쓰고, AI의 '정답 같다'는 판정으로 대체하지 않는다.

한 문서의 여러 근거를 일일이 트레이에 올리는 부담을 줄이려면 문서 첨부를 허용하고 해당 문서의 문장을 후보로 풀어 준다. 사용자가 어떤 사실을 연결했는지 해석한 뒤 실제 소유·문장·모순을 검사한다. 조건을 충족해도 엉뚱한 인물을 추궁하면 그 인물의 진술은 바뀌지 않는다.

## 6. 수사팀 AI 계약

입력: 플레이어 요청, 직전 수사팀 대화, 소유 자료, 알려진 조사 대상, 공개 가능한 GT-R 카탈로그. 출력: 조사 ID 배열 또는 명확화/지원하지 않는 요청. 결과의 실제 텍스트는 고정 자료에서 읽는다.

조사 ID가 존재하고 필요한 대상이 확인되며 범위가 허용되는지 엔진이 검증한다. 연속 요청은 카탈로그 의존 순서로 한 번씩 실행한다. '예약 시간도 알려줘'는 GT-R11, '지문 주인 확인'은 GT-R13, '전부 확인'은 준비된 사건 관련 조사 전체에 매핑한다. 단어·표현이 달라도 동일 요청을 인식한다.

수사팀은 미보유 증거의 결과·범인 정답을 자유 문장으로 만들지 않는다. '몇 시에 죽었는지 확정해'에 자백 전 20:31을 반환하지 않는다. 가능한 시간 범위와 그 근거는 보유 자료로만 요약한다. 인물·가족·금융기관의 새 이름, 실존 개인정보, 다른 방·통로·도구를 만들지 않는다.

한 번의 유효한 요청을 가능한 한 한 해석 호출과 고정 응답으로 처리한다. 별도 말투 호출이 반드시 필요한 구조로 늘리지 않는다. 기존 오류·대기·재시도 규칙을 유지하고, AI 실패가 곧 거절이나 오답처럼 보이지 않게 한다. 네트워크 결과 반영과 게임 상태 변경을 한 번만 수행한다.

## 7. 저장과 진행 조건

구 저장 키는 현재 `bellua-text-save-v1`다. 새 사건은 `gold-trophy-save-v1` 등 독립 키를 쓰고 저장물에 `caseId`를 넣는다. 상태 구조를 확장하면 version을 올리고 지원하지 않는 옛 저장을 자동 새 사건에 섞지 않는다. 구 저장 데이터를 일괄 삭제하지 않는다.

용의자 `PersonId`는 A/B/C로 유지한다. 수사팀은 별도 `teamChat` 또는 `ChatTarget = PersonId | 'team'`으로 대화 UI만 확장하고 범인·초상·인물 리스트에 포함하지 않는다. 현재 탭 타입에 investigation을 추가하거나 같은 기능을 별도 패널로 두되 자료·인물 전환 후 결과를 잃지 않는다.

논파 C-L01~03은 독립적으로 성공 가능하다. C-L04 최종 성공은 이전의 성공 횟수로 잠그지 않는다. 다만 해당 거짓 주장을 지적했거나 범행·예약 조작을 최종적으로 설명해야 한다. 모든 자료를 얻었다는 이유만으로 자동 자백하지 않는다. 최종 자백은 관련 나머지 거짓말을 닫고 보고서가 정리 화면으로 이어진다.
